# Recreating Literary Works Using ChatGPT and Evaluating Results with NLP Analysis

A Data Science and Analytical Storytelling thesis evaluating how well ChatGPT recreates six classic poems in the style of
other poets, scored with sentiment analysis, lexical diversity metrics, and two
AI-text detectors.

> **Note on the GitHub language bar:** this repo will show as mostly HTML/binary
> unless your client honors `.gitattributes` — that's just the rendered, self-contained
> output pages and generated media. The actual project is **Quarto + Python**
> (analysis, in the `.qmd` files) with **R** used only for publishing to RPubs.

## Setup

You need **Quarto** and **Python** to render any of the three `.qmd` files.
**R** is only needed if you also want to publish to RPubs yourself.

### 1. Quarto

Install the [Quarto CLI](https://quarto.org/docs/get-started/) (this project was
built and tested against Quarto 1.9.38).

### 2. Python environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Quarto's Jupyter engine needs a kernel literally named `python3` (that's what
each file's YAML header — `jupyter: python3` — asks for):

```bash
python -m ipykernel install --user --name python3
```

### 3. Render

```bash
quarto render ThesisStoryTelling.qmd --to html
quarto render PoemAudioLibrary.qmd --to html
quarto render ThesisSlides.qmd --to html
```

Each file sets `embed-resources: true`, so the output `.html` is a single
self-contained file — all figures, audio, and slide images are embedded as
base64 data, with no external `_files/` folder needed. That's what makes them
safe to upload as-is to RPubs.

`PoemAudioLibrary.qmd` and `ThesisSlides.qmd` read from `audio/` and `slides/`
respectively at render time — those folders need to exist alongside the `.qmd`
files (they're committed to this repo, so a fresh clone has everything needed).

### 4. Publishing to RPubs (optional)

Publishing was done with R's `rsconnect` package, not Quarto's own publish
command, so the same RPubs document could be updated in place across renders
rather than creating a new page every time. Requires R and the `rsconnect`
package:

```r
install.packages("rsconnect")
```

```r
library(rsconnect)
rpubsUpload(
  title = "<title>",
  contentFile = "<file>.html",
  originalDoc = "<file>.qmd",
  id = "<existing appId, to update a page instead of creating a new one>"
)
```

The `id` for each of this repo's three pages is stored locally in
`rsconnect/documents/<file>.qmd/rpubs.com/rpubs/Publish Document.dcf`
(gitignored — regenerate it yourself, or ask whoever has publish access).

## Regenerating the audio and slide assets

These are one-time asset-generation steps, independent of rendering the
`.qmd` files. You only need to redo them if the underlying poem text or slide
deck changes.

**Audio** (`audio/*.m4a`) — macOS only, uses the built-in `say` command:

```bash
say -v Moira -f <poem-text-file>.txt -o out.aiff
afconvert -f m4af -d aac -b 32000 -c 1 out.aiff out.m4a
```

`poems_data.json` holds the exact text for each of the 42 clips; it was
extracted from the `data = [...]` literal in `ThesisStoryTelling.qmd`.

**Slides** (`slides/*.jpg`) — rasterized from `ThesisPresentation.pdf` with
[PyMuPDF](https://pymupdf.readthedocs.io/) (`pip install pymupdf`, listed as
an optional dependency in `requirements.txt`):

```python
import fitz  # pymupdf
doc = fitz.open("ThesisPresentation.pdf")
for i, page in enumerate(doc, 1):
    pix = page.get_pixmap(matrix=fitz.Matrix(1.5, 1.5))
    pix.save(f"slides/slide-{i:02d}.jpg", jpg_quality=85)
```
